# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Changed
- **Analysis-Only Scope (chore/analysis-only-strip)**: Stripped the chat agent, document-edit/TipTap editing, Supabase auth/users, subscriptions, daily cron, and email notification features from both backend and frontend, leaving a single-tenant court-analysis application.
  - **Backend**: Removed `chatAgent.js`, `db.js`, Supabase middleware/services, trial quota, email service, cron, and uploads handling. Added `services/localStore.js` — a JSON-file persistence store (`backend/data/analysis/runs.json` + `events.json`, override via `ANALYSIS_DATA_DIR`) replacing Supabase-backed analysis history. Rewrote `server.js` as an analysis-only Express app exposing `POST /api/court-analysis` plus `GET /api/analysis/runs`, `/:id`, `/:id/full`, `/:id/events`, `/:id/stream`, and `/health`, with p-queue (concurrency 1) and IP rate limiters retained.
  - **Frontend**: Removed chat UI, `AuthContext`/`ChatContext`, `useStreamingAPI`/`useFileUpload`, TipTap editor stack, and Supabase client. Added `hooks/useCourtAnalysisStream.js` (typed-query payload construction + SSE handling, no token) and `components/Dashboard/DashboardHeader.jsx`. Dashboard is now the sole analysis surface; `/` redirects to `/dashboard`.
  - **Testing**: Added `backend/tests/localStore.test.js` and `backend/tests/analysis-runs-api.test.js`; added `simple-chat/src/hooks/__tests__/useCourtAnalysisStream.test.js`; rewrote analysis E2E/stream-handler/SSE/`NewAnalysisModal`/`useAnalysisRuns`/`useAnalysisRunDetail`/`AnalysisRunDetailPage` tests for the no-auth flow. Fixed pre-existing lint/test issues (`MermaidDiagram` unused ref, `errorHandler` CRA `import.meta` parse failure, `env.js` unused import).
  - **Docs/Env**: Updated `README.md`, `AGENTS.md`, `CHANGELOG.md`, and `backend/TODO.md`; removed Supabase/trial secrets from `backend/.env` and `simple-chat/.env.local`; gitignored `backend/data/`; logged the auth-removal decision in the Storybook analysis-detail `README.mdx`.

### Added
- **Court Analysis Live Reasoning Verification (Phase 2 tooling)**: Added `backend/scripts/verify-live-reasoning.js` and the `verify:reasoning` npm script to run the full cluster-scoped reasoning chain (`ClusterEvidencePackage` build/validate -> `generateClusterReport` -> `validateReport`) against real Gemini using the frozen `66124057408-baseline.json` fixture (ST-2/2013 Kerum, 13 individual analyses), writing the resulting report to `backend/test-artifacts/live-reasoning-report.json`.
- **Court Analysis Observability (Logging)**: Added `backend/helpers/logger.js` (dependency-free, JSON-lines, leveled via `LOG_LEVEL`) and wired structured logging into `pipeline.js` stage transitions (discovery, grouping, per-case analysis, reasoning report, completion, errors) and `reportService.js` retrieval/rerank/synthesize/verify outcomes. Logs redact 11-digit OIBs and API keys/tokens.
- **Court Analysis Reasoning (chunker)**: Rewrote the document chunker as a single cursor-based sliding-window implementation with accurate `metadata.startIndex`/`endIndex` (trimmed spans into the original text), a forward-progress guarantee on long separator-free runs, and property-test invariants for content preservation, span accuracy, size caps, monotonic ordering, and full non-whitespace coverage.
- **Court Analysis Reasoning Evidence Handoff (C-08)**: Added validation for `ClusterEvidencePackage` invariants and made structured report synthesis consume the package directly, preserving selected-cluster metadata, secondary-cluster separation, document provenance, selection diagnostics, and expansion metadata in reasoning evidence/report metadata.

### Known Issues
- **Gemini free-tier quota blocks live reasoning runs**: `generate_content_free_tier_requests` caps at 20 requests/day for `gemini-2.5-flash` on the free plan; the reasoning chain burns several requests per run plus retries, so `verify:reasoning` is quota-blocked until a paid API key is configured. The quota dashboard can report 100% available while the API still returns 429 — trust the raw API response (`https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent`) over the dashboard.
- **LangChain `@langchain/google-genai` hangs on 429**: `gemini.invoke()` does not surface HTTP 429 errors and hangs indefinitely instead of rejecting, so `withGeminiRetry` (which only retries on thrown errors) never fires. This makes any Gemini-backed run appear to stall silently during rate-limit spikes. Recommended fix: pass a `timeout` to the `ChatGoogleGenerativeAI` model config or wrap `invoke` with an AbortController timeout.
- **Court Analysis Evidence Package (C-07)**: Added an explicit `ClusterEvidencePackage` handoff for the selected primary cluster, preserving selected-cluster identity, discovery/selection/expansion metadata, entries, document links, and acquisition/source provenance while keeping secondary clusters separate in discovery output.
